# Self Pause 状態遷移仕様書

## 1. 論理状態

- `LOCKED`: 使用禁止状態
- `UNLOCKED`: 使用可能状態
- `UNLOCK_COUNTDOWN`: 使用禁止状態から使用可能状態へ移行中
- `LOCK_COUNTDOWN`: 使用可能状態から使用禁止状態へ移行中
- `ACTIVITY_SELECTION`: 使用禁止状態への移行後、直前の活動内容を選択中

## 2. 初回起動

```text
未初期化
  ↓
LOCKEDを保存
  ↓
UNLOCK_COUNTDOWNを開始（10秒）
  ↓ 10秒完了
UNLOCKEDへ遷移
```

## 3. 通常の状態遷移

```text
UNLOCKED
  │ アプリが前面に復帰
  ▼
LOCK_COUNTDOWN
  │ 10秒完了
  ▼
LOCKED
  │ 活動内容を選択
  ▼
履歴を確定
  │ アプリが前面に復帰
  ▼
UNLOCK_COUNTDOWN
  │ 10秒完了
  ▼
UNLOCKED
```

## 4. 中断ルール

### バックグラウンド移行

- カウントダウン中に`hidden`になった場合、カウントダウンを破棄する。
- 状態はカウントダウン開始前の状態のまま保持する。
- 次回`visible`時に10秒から再開する。

### ブラウザの戻る操作

- カウントダウン中の戻る操作では、カウントダウンを破棄する。
- 状態は変更しない。
- 次回復帰時に10秒から再開する。

### 再起動

- localStorageから最後に確定した論理状態を読み込む。
- `LOCKED`なら解禁カウントダウンを開始する。
- `UNLOCKED`なら終了カウントダウンを開始する。
- カウントダウン途中の状態は永続化しない。

## 5. 状態確定の原則

- 10秒のカウントダウン完了前に状態を変更しない。
- アニメーションの途中で履歴を確定しない。
- 終了カウントダウン完了後、終了時刻を記録する。
- その後、直前の活動内容を選択して履歴を確定する。
- 活動内容が選択されるまで、未確定履歴として保存してもよい。

## 6. 活動時間の扱い

- 使用開始時刻: `UNLOCKED`への移行完了時刻
- 使用終了時刻: `LOCKED`への移行完了時刻
- 使用時間: 使用終了時刻 - 使用開始時刻
- 活動内容: 使用禁止状態への移行後に選択された直前の活動

## 7. 解禁前のタイマー選択（設定で有効にした場合のみ）

- 既定ではタイマーボタンを表示せず、前面復帰時にすぐ`UNLOCK_COUNTDOWN`を開始する（追加の確認操作を要求しない）。
- 設定画面で「起動時に利用時間のボタンを表示する」をオンにした場合、使用禁止状態（未確定履歴なし）で前面に復帰すると、`TIMER_SELECTION`として閉じた扉の手前に6つのボタン（既定: 5分・15分・30分・1時間・2時間・制限なし）を表示する。
- ボタンを押した時点で`UNLOCK_COUNTDOWN`を開始し、同時に扉が開くアニメーションを再生する。
- 選んだ利用時間は`UNLOCKED`への移行完了時刻から計り、`activeSession.timerEndsAt`に保存する。
- 利用時間が終了しても状態は変更しない。終了1分前に1回、終了後は`UNLOCKED`が続く間10秒ごとに通知を送る（終了カウントダウンの実行中は送らない）。
- 通知はページ自身のタイマーから送るため、バックグラウンドではブラウザの制限により間隔が延びたり届かなかったりする。
- ボタン1〜5の利用時間（分）とボタン表示の有無は設定画面で変更でき、`settings.timerPresets`・`settings.showTimerButtons`に保存する。
- 下部ナビ（ホーム・履歴・設定）はアニメーション中も操作できる。カウントダウン中に他画面へ移動した場合はカウントダウンを中断し、ホームへ戻った時点で最初からやり直す。
